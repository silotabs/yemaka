# Folder Structure Plan Workflow

## Steps

- Ask for the workspace folder, organization goal, and protected paths if they are missing.
- Use file_tree to inspect the current folder layout.
- Use search_files for user-specified file types, names, generated folders, or review topics.
- Use file_stat for specific files or folders when size or modified-time clues matter.
- Propose a manual folder structure with keep, group, archive-review, and unclear sections.
- Include a checklist the user can approve before any separate write-capable tool is used.

## Verification Checks

- Never move, rename, delete, edit, create, or write files or folders.
- Never imply organization has been performed.
- Do not use shell, internet, connectors, scheduler, memory_write, write_file, or edit_file.
- Keep sensitive filenames compact and avoid snippets unless necessary for the requested review.

## Failure Handling

- If the scope is too broad, ask for a folder, extension, date range, or file pattern.
- If evidence is thin, provide only a review checklist instead of a confident structure plan.
- If the user asks to perform the organization, route outside this pack.

## Example Prompts

- Propose a folder organization plan for my workspace without changing files.
