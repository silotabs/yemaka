# Repair Visit Prep Workflow

## Steps

- Ask for pasted notes, visit context, or local document scope if missing.
- Use rag_search for local repair notes, manuals, warranties, service records, or property notes.
- Use memory_search only for prep preferences or local context boundaries, not sensitive identifiers.
- Organize issue summary, timeline, documents to gather, questions, access reminders, supplies, and professional cautions.
- Keep supplies to safe prep items: notes, photos, model or warranty details, clear access, towels, bucket, flashlight, or gloves.
- Keep the output as reviewable notes for the user or a qualified professional.

## Verification Checks

- Do not use internet search, connectors, scheduler, shell, file writes, or memory writes.
- Do not provide hazardous repair instructions, bypass safety devices, or guide electrical, gas, plumbing, structural, roofing, or other dangerous work.
- Do not schedule visits, contact providers, buy supplies, update files, store details, diagnose hidden failures, or replace licensed advice.
- Avoid repeating addresses, access codes, account, warranty, tenant, contact, payment, or serial details unless required.

## Failure Handling

- If notes are missing, ask for pasted notes or local document scope.
- If notes imply urgent danger, active leak, fire risk, gas smell, electrical hazard, structural movement, mold, asbestos, carbon monoxide, or injury risk, tell the user to stop and contact emergency services, utilities, or a qualified professional as appropriate.
- If asked for repair steps, live requirements, parts compatibility, permit rules, or code compliance, route outside this pack or require approved current guidance.
